## What was wrong and what the change does

Both bugs (review n° 19 and n° 20) were reproduced in the SSE and FPU builds before any change. hausdorff() returned +oo as soon as any bound of either interval was infinite, except for two entire intervals. So hausdorff([1,+oo],[1,+oo]) and hausdorff([1,+oo],[2,+oo]) were +oo (the second is really 1), and a fixed-point loop on a box with an unbounded side never stopped. Both builds now use one formula, max(d(a,c), d(b,e)) with d(x,y) = 0 when x == y and max(x-y, y-x) rounded upward otherwise. Equal infinite bounds are at distance 0, and a bound infinite in only one interval gives +oo through inf - x. The old 16-case switch of the SSE build and the isinf branch of the FPU build are gone, and inf - inf is never computed. nb_fp_numbers() numbered the doubles by the bits of a and b, sign bit included. With a lower bound -0.0 (which `-0.0 >= 0` accepts, and which [1,2]-1 really has) or with a < 0 and b = +0, the difference of bit patterns wrapped around: nb_fp_numbers(-0.0, 1.0) and nb_fp_numbers(-1.0, 0.0) were 13830554455654793217 instead of 4607182418800017409. It now takes the bits of std::fabs(a) and std::fabs(b), so -0 and +0 are one number. Two GAOL 4 checks in tests/interval_functions.cpp (lines 64 and 69) asserted +oo for hausdorff([3,+oo],[5,+oo]) and hausdorff([-oo,4],[-oo,6]); they now expect 2. The Doxygen comments, the manual and doc/tests.md are updated.

## Tests

tests/other_functions.cpp: hausdorff_of_infinite_bounds() checks 1225 pairs of intervals with bounds in {-oo,-2,-1,-0,0,1,2,+oo}. The reference is computed apart from the library: exact Dyadic/Exact arithmetic with is_tightest_upper_bound(), +oo for a bound infinite in one interval only, and 0 for equal infinite bounds. It also checks symmetry, hausdorff([1,+oo],[1,+oo]) == 0, hausdorff([1,+oo],[2,+oo]) == 1, hausdorff([-oo,1],[-oo,3]) == 2, hausdorff([1,+oo],[1,2]) == +oo, hausdorff([1,+oo],[-oo,1]) == +oo, and hausdorff(x,x) == 0 for four unbounded intervals. nb_fp_numbers_across_zero() checks the 106 pairs [i, j] of multiples of denorm_min (consecutive doubles, count j-i+1, with +0 and -0 in every argument position) and 14 fixed counts from the bit patterns of 1.0 and DBL_MAX. Those cover [-0,1], [-1,+0], [-1,-0], [-1,1], [-0,MAX], [-MAX,+0], [-MAX,MAX] and the four zero pairs. It also checks nb_fp_numbers over [1,2]-1 and 1-[1,2], computed with intervals. Both new functions are called from main(). tests/interval_functions.cpp: the two GAOL 4 checks now expect 2.

## Behaviour change

hausdorff(x, y): equal bounds, infinite ones included, are at distance 0. hausdorff([1,+oo],[1,+oo]) is now 0 (was +oo), hausdorff([1,+oo],[2,+oo]) is 1 (was +oo), hausdorff([-oo,4],[-oo,6]) is 2 (was +oo). A bound infinite in one interval only still gives +oo, the entire intervals still give 0, and an empty interval still gives NaN. The result is the same in the SSE and FPU builds. nb_fp_numbers(-0.0, 1.0) and nb_fp_numbers(-1.0, 0.0) are now 4607182418800017409 (were 13830554455654793217), as is nb_fp_numbers(0.0, 1.0). nb_fp_numbers(-0.0, 0.0) is still 1, and the count for [1,2]-1 is now right whatever the sign of its zero bound.

## Risks

Low. The infinite-bound cases of hausdorff() now do the rounding-direction check and the arithmetic like the finite ones (about 14 ns against 4.5 ns before, measured with GCC -O2 on a busy machine), so a hot loop of hausdorff() on intervals with an infinite bound is slower. The finite case is unchanged (about 14 ns). hausdorff() no longer uses SSE2 intrinsics (the removed switch was the only use in that function). The equality tests keep inf - inf (a NaN, and a raised invalid flag) from ever being evaluated. Behaviour on x87 (32-bit) is the same code path as before for finite values, and the new test code uses only portable constructs (anonymous struct array, lambdas, std::vector); the CI platforms could not be run here. The FPU comparison `a == c` on doubles is exact and does not depend on the extended precision. Two existing GAOL 4 unit checks (interval_functions.cpp lines 64 and 69) were changed because they asserted the old, wrong values.

## Open questions and decisions for the maintainer

1. Performance: the old SSE code returned +oo (or 0) for infinite bounds without touching the rounding mode. If hausdorff() on unbounded intervals must stay as fast as before, an early exit is possible (return +oo when a bound is infinite in one interval only, and enter the rounding only for finite pairs). I judged the single formula simpler and kept it. 2. `[1,2] - 1` (and `1 - [1,2]`) has a -0 lower bound (a +0 or -0 upper bound for the second), which is legal but surprising; nb_fp_numbers() no longer depends on it. Whether interval operations should normalise -0 to +0 is a decision for the maintainer, and I did not touch it. 3. doc/differences.md line 288 already has a `hausdorff()` bullet (rounded upward); the ledger text above is a separate bullet, or can be merged into that one. 4. tests/float_functions.cpp, disabled with GAOL_FLOAT_INTERVALS, calls nb_fp_numbers with float arguments, and does not test zero or infinite cases; it is unaffected.
