## Open questions and decisions for the maintainer

Left out, as asked: macOS, Windows, containers.yml and build-systems.yml. (a) macOS and Windows probably already run the comma part (fr_FR.UTF-8, French_France.1252), but nothing shows it: `sh .github/scripts/comma-locale.sh check build` after their tests would, unchanged on macOS (POSIX sh and grep); to decide once the Linux logs are seen. (b) Debian containers need `apt-get install locales` and an entry in /etc/locale.gen (Debian's locale-gen takes no name, checked on 2.36-9+deb12u9 and 2.41-12+deb13u4) or localedef; Alpine (musl) and the manylinux images have no comma locale to generate as such. (c) The Ubuntu jobs of build-systems.yml (autotools, meson) run numbers too, and tests.sh builds it against the installed GAOL; their logs are tests/numbers.log, build-meson/meson-logs/testlog.txt and numbers.log, so the guard would need another log path. Alternative design, not done because it changes C++ that point 18 edits: a variable read by tests/numbers.cpp (say GAOL_TESTS_REQUIRE_COMMA_LOCALE) making the test itself fail, which would serve every platform without reading ctest's log. Other things noticed, not fixed: tests/fetch_content and tests/find_package give numbers no TIMEOUT (tests/CMakeLists.txt sets 300 s for numbers only there), so a hang would run until the 60-minute job limit; the Ubuntu 26.04 image readme announces that the Ubuntu 22 images begin deprecation on 17 September and are unsupported by 17 April, which will remove the 22.04 jobs of linux.yml.
