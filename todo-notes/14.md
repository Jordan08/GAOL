## Behaviour change

For the users of GAOL v5 (and of GAOL 4): what() of every GAOL exception (gaol_exception, input_format_error, invalid_action_error, unavailable_feature_error) returns the explanation, or "gaol_exception" when there is none, where it returned "std::exception". A catch (const std::exception& e) handler now prints the explanation, and an uncaught GAOL exception ends the program with "what():  <explanation>" (libstdc++). operator<< of an exception writes "file, line n: exception thrown: explanation" (no colon and explanation when there is none) where it wrote "file, line n: exception std::exception thrown: explanation". explanation(), file() and line() are unchanged.

## API and ABI

New public virtual member const char* gaol_core::gaol_exception::what() const noexcept override, defined in gaol/gaol_exceptions.cpp and exported with the class; ~gaol_exception() is now marked override (same exception specification, implicitly noexcept). what() is the key function of gaol_exception, so its vtable and typeinfo are now defined only in libgaol (user code only references them); derived classes keep their own inline constructors. The text written by operator<< changes (see behaviour_change). No new installed file, no build-file change, no change to CMakeLists.txt, Makefile.am or meson.build.

## Open questions and decisions for the maintainer

Choices for the maintainer: (1) the fixed text when there is no explanation is "gaol_exception", as examples/examples.md item 15 proposes; another text ("GAOL exception", the class name through typeid) would be a one-line change in gaol_exceptions.cpp and in the test. (2) operator<< keeps the words "exception ... thrown" and drops only what(); the alternative "file, line n: explanation" is shorter. (3) I corrected in the manual the return type of explanation() (const char* const, which the header never had since GAOL 4: it returns std::string) because the new what() entry sits under it and says it returns the same text; drop that line from manual/v5/gaol.tex if a strictly minimal diff is wanted. Bookkeeping left to the orchestrator: examples/examples.md still lists number 15 as open (row 15 of section 5.2 needs "**Fixed**", item 15 of Appendix B "(applied)", the sentences counting the applied numbers "1, 9, 11, 13, 14 and 18" in section 5 and Appendix B, and item 9 of Priority 3/4 "make what() the explanation"); I did not edit it to avoid conflicts between the points. coverage/README.md (generated) lists the uncovered lines of gaol/gaol_exceptions.cpp, which have moved and are now covered. Other things noticed, not fixed: the constructors taking a const char* explanation give a null pointer to std::string (undefined; libstdc++ throws std::logic_error "basic_string::_M_construct null not valid" while the exception is being built, also through gaol_ERROR(excep, NULL)); the manual documents the constructors with const char* e only, the classes also take const string&; the \defmethod macro of manual/v5/manual.cls can leave the header of an entry alone at the bottom of a page (the what() entry falls that way on pages 80-81 of the current layout, which will change with the other points); operator<< calls explanation() twice, so copies the string twice (harmless).

## For doc/differences.md

- **`what()` of GAOL's exceptions is their explanation.** `gaol_exception`
  overrides `what()`: it returns the explanation, or `gaol_exception` where
  there is none, so that `catch (const std::exception& e)` and the message of
  an exception that nothing catches say what went wrong. GAOL left the `what()`
  of `std::exception`, which is `std::exception` with libstdc++ and libc++,
  whatever the error. `operator<<` of an exception writes the explanation once,
  `file, line n: exception thrown: explanation`; it wrote `what()` next to it,
  `file, line n: exception std::exception thrown: explanation`. (Suggested
  place: after the bullet on `operator>>`.)
